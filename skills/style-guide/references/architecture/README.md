# Архитектура

Этот раздел описывает не сами архитектуры, а решения команды в тех вопросах, где выбранная архитектура оставляет
несколько допустимых вариантов.

Правила архитектуры бери из её актуальной документации и agent skill. Локальный профиль загружай дополнительно: он
фиксирует принятые командой соглашения, но не пересказывает базовую модель, слои, модули и зависимости.

## Профили

| Архитектура | Профиль | Применение |
| --- | --- | --- |
| SLM Design | [`slm-design/README.md`](slm-design/README.md) | Только для проектов, в которых команда выбрала SLM |

## Порядок применения

1. Для существующего проекта определи принятую архитектуру по project instructions, структуре и архитектурным решениям.
2. Загрузи источник правил этой архитектуры.
3. Загрузи соответствующий локальный профиль и примени относящиеся к задаче решения команды.
4. Учитывай project-specific ADR и соглашения: они могут уточнять либо заменять общую policy style guide.

Не вводи другую архитектуру или массовую миграцию в рамках локальной feature-задачи. Для нового проекта архитектуру
выбирает команда; наличие профиля в style guide само по себе не делает её обязательной.

## Требования к профилю

Каждое правило профиля должно отвечать на четыре вопроса:

- какой выбор оставляет архитектура;
- какое решение приняла команда;
- где это решение применяется;
- как проверить его выполнение.

Если документ только повторяет источник архитектуры и не фиксирует дополнительного решения команды, ему не место в
этом разделе.
