# SLM Design

[SLM Design](https://github.com/gromlab-ru/slm-design) является предпочтительной архитектурной моделью frontend-приложения при строгом применении style guide.

## Перед работой

1. Найди и загрузи agent skill `slm-design`.
2. Используй skill и актуальную документацию SLM Design как источник архитектурных правил.
3. Только после определения владельца, слоя, границы модуля и public API применяй code style и framework-правила.

Если skill недоступен, используй [официальную документацию SLM Design](https://gromlab-ru.github.io/slm-design/). Не восстанавливай архитектурные правила по памяти.

## Область ответственности

SLM Design определяет:

- владельца поведения и состояния;
- роли слоёв;
- границы модулей;
- public API и допустимые зависимости;
- место React-компонентов, hooks, stores, REST-клиентов и subscriptions относительно владельца.

React-компонент, hook, Zustand store или SWR hook является механизмом реализации и не становится архитектурным владельцем только из-за технической роли.

## Приоритет проекта

- В существующем проекте не вводи SLM параллельно другой архитектуре без явной задачи на миграцию.
- Если проект закрепляет SLM Design или пользователь прямо требует style guide, применяй SLM ко всем новым архитектурным решениям.
- Не выполняй массовое перемещение существующих модулей в рамках локальной feature-задачи.

## Проверка

- Перед физическим размещением кода определён единственный владелец ответственности.
- Межмодульные зависимости проходят через разрешённый public API.
- Framework и library choices не подменяют архитектурное решение.
- Для архитектурной задачи загружен skill `slm-design` или официальная документация.
